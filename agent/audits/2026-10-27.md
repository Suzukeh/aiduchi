## 3. 追加検証（2本失敗）

同一room・同一parentの兄弟ノードを2つ作り、`README.md` に `branch-A` / `branch-B` を保存してUIを操作した。

```
✘ 保存済み内容は編集開始時にも表示される
  Expected: "branch-A"   Received: ""        （.cm-content が空）

✘ 分岐Bの編集保存に分岐Aの内容が混入しない
  {"sharedA":"","sharedB":""}
  {"branchBExpected":"branch-B","branchBActuallySaved":""}
  Expected: "branch-B"   Received: ""        （保存後の新ノードのスナップショット）
```

読み取れること:

1. **閲覧（`pre`）では正しい内容が出る**。壊れるのは編集モードに入った時点。
2. 編集モードのエディタは空。そのまま保存すると新ノードのスナップショットが空文字で保存される。元のスナップショット自体は消えていないが、UI操作としては内容の喪失。
3. 原因候補は `apps/web/src/components/FilesPanel.tsx`。`t.length === 0` のときだけスナップショット内容を流し込むため、「未初期化」と「意図的な空ファイル」を区別できず、一度空の `Y.Text` ができると復元されない。
4. `apps/web/src/store.ts` の `getYFiles()` は `doc.getMap<Y.Text>("files")`。キーはパスのみで**分岐の識別子を含まない**ため、別分岐の同名ファイルが同じ共同編集オブジェクトに接続される。
5. 今回は空文字化までを動的に確認した。**異なる非空内容どうしの混入は、この手順では実証できていない**（両方空になったため）。構造上の欠陥として記録し、実証済みとは書かない。
